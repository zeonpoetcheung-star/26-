# Problem 2｜Candidate Analysis & Modeling Report

## 1. 问题定位

P2 的关键不再是确定性套利，而是：

> 每天 0:00 在只能利用历史信息的条件下预测当天净负荷，并据此制定计划购电；实际运行中出现的未覆盖缺口按 5 倍电价紧急补购。

因此最终结构为“预测 + 优化 + 实际回放”，而不是直接把附件2当天真实负荷/PV送入优化器。

## 2. 信息集

在日期 d 的 0:00，只允许使用：
- d-1 及更早的实际负荷、PV；
- 固定电价；
- 当前真实 SOC；
- 已冻结的历史预测账本和模型状态。

禁止：
- 当天未来 actual；
- 后续日期 actual；
- random split 后回填；
- 用全年实现费用决定历史时点使用哪个模型。

## 3. 预测层

净负荷：

\[
N_{d,t} = L_{d,t} - PV_{d,t}.
\]

历史基准：

\[
b_{d,t} = L_{d-7,t} - PV_{d-1,t}.
\]

LightGBM 学习基准残差的 Q50 / Q80：

\[
r_{d,t} = N_{d,t} - b_{d,t}.
\]

固定 18 个因果特征，按 expanding-window、每 7 天重新训练，全年 96 次 fit。

每天是否采用 LightGBM，不根据当天实际结果，而根据此前 28 天已发布预测的真实历史表现决定。正式期 334 天中，LightGBM 被采用 301 天。

## 4. 风险需求与 5 倍紧急购电

在无储能单时段近似中：

\[
\min_g \left[p g + 5p\,\mathbb E(X-g)^+\right]
\]

给出约 0.8 的临界分位。Candidate 将 Q80 作为风险需求轨迹，但不宣称“有储能后逐槽 Q80 是严格随机最优”。

## 5. 48h 滚动 LP

每天内部规划未来 288 个 10 min 槽，只冻结第一天的 144 个计划购电量。

\[
\min \sum_k p_k G_k
\]

约束：

\[
G_k + D_k = \hat n_k + C_k + W_k,
\]

\[
S_k = S_{k-1} + 0.9C_k - D_k/0.9,
\]

\[
1200\le S_k\le10800,
\]

\[
0\le C_k,D_k\le 5000/6.
\]

内部 48h 终端采用：

\[
S_{288}=S_0,
\]

但不要求：

\[
S_{144}=S_0.
\]

实际日终 SOC 连续传给下一天。

## 6. 实际执行与结算

全天计划 `G_plan` 在 0:00 后不改变。

实际运行时只允许使用当前槽实际负荷/PV和当前 SOC 做储能响应。若仍不足，产生紧急购电。

实际结算：

\[
J = \sum_t p_tG^{plan}_t
 + \sum_t 5p_tE^{emg}_t.
\]

计划电量即使没有实际接收，也不退款。

## 7. 机器学习的实际贡献

在共同可评价日期上，LightGBM 相对历史基准约：
- Q50 MAE 下降 8.74%；
- Q50 RMSE 下降 9.99%；
- Q80 电价加权分位损失下降 10.06%。

MAIN 相比 `BASELINE_ONLY_Q80`：
- 实际总费用减少约 148,548.66 元；
- 降幅约 1.05%。

因此机器学习不是装饰性模块，确实进入正式购电决策并形成端到端经济改善。

## 8. 为什么没有继续使用更复杂模型

三类定向改进均未击败原 MAIN：
- SAA 场景风险优化：更保守，但总费用上升；
- EWMA / Harmonic-EWMA：部分校准指标改善，但预测主要损失和总费用变差；
- Causal MPC：固定计划下总费用显著上升。

因此 Candidate 选择“经过多个限定改进仍保持最佳的 MAIN”，而不是继续开放式搜索新的深度学习或控制模型。
