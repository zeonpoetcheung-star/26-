## OI-02｜附件3日期列的共享字符串空白编码

**级别**：Critical for preprocessing  
**最迟解决阶段**：A-1 Preprocessing

复核工作簿的语义值与 OOXML 后确认：

```text
2025-x-x   0:00
""         6:00
""         12:00
""         18:00
```

6:00、12:00、18:00 行的日期单元格语义值为空字符串。OOXML 中可见 `t="s"` 与 `<v>28</v>`，其中 `28` 是 sharedStrings 的索引；索引 28 对应空字符串，因此不能把 `28` 当作日期列的业务字面值。

**允许的处理原则**：

- 全表验证 365 个四行块；
- 每块首行必须是连续、唯一、可解析的日期，发布时间为 0:00；
- 每块后3行日期语义值必须为空，发布时间依次为 6:00、12:00、18:00；
- 结构完全通过后，可基于同块 0:00 日期派生后3行 `issue_date`；
- 保留语义原始值，并尽可能保留 OOXML `<v>28</v>` / shared-string-resolution 的审计证据；
- 派生日期必须带 `date_derivation`；
- 任一块异常则阻塞 Preprocessing。

这属于确定性结构恢复，不属于统计填补，也不允许覆盖原始审计字段。

## OI-03｜“充放电效率90%”的数学含义不唯一

**级别**：Critical for model  
**最迟解决阶段**：A-4 Model Planning

题面只写“储能设备的充放电效率为90%”，未明确：

1. 充电效率 \(\eta_c=0.9\) 且放电效率 \(\eta_d=0.9\)；
2. 还是整个充放电往返效率为0.9；
3. 输出表中的“充电量/放电量”究竟记录电池侧还是微网侧能量。

这些定义会改变储能状态方程和成本。

**要求**：正式模型前必须选定清晰口径；若题面无法进一步消歧，应作为显式模型假设，并考虑最小必要的敏感性核验。

## OI-04｜P2/P3/P4 是否要求每日 S(0)=S(24)，以及跨日状态如何衔接

**级别**：Critical  
**最迟解决阶段**：A-4 Model Planning

P1 明确规定 0:00 与24:00 储电量相同。P2/P3/P4 没有重复这一条件。

附录只给：

- 2025-01-01 0:00 初始储电量为6000 kWh；
- 后继运行储电量保持在1200—10800 kWh。

因此不能默认每一天都重置到6000，也不能未经说明强制每日首尾相等。

同时正式结果从 2025-02-01 才开始，而初始状态给在 2025-01-01。

**需决定**：

- 是否连续模拟1月以得到2月1日初始状态；
- 每天的终态是否自然传递到下一天；
- 是否需要终端价值/终端约束避免最后一天透支储能。

## OI-05｜P2 每天0:00制定计划时可使用的信息集合未直接给出

**级别**：Critical  
**最迟解决阶段**：A-3 EDA 后、A-4 Model Planning

附件2提供的是全年“实际”负载和实际光伏，但题目要求每天0:00制定当天计划。

若直接用当天未来实际数据生成当天0:00计划，会产生未来信息泄漏，除非论文明确把问题解释为事后完全信息优化；这一解释与“每天0:00制定计划”的表述存在明显冲突。

**需要建立**：

- 每个决策日可用的历史窗口；
- 是否允许使用日历信息；
- 预测/估计当天未来负载、PV的规则；
- 2025年1月数据如何作为2月起正式输出前的历史信息。

A-1/A-2/A-3 只能提供数据事实，不得自行选预测模型。

## OI-07｜P3 调整购电费用的精确结算公式需形式化

**级别**：Critical  
**最迟解决阶段**：A-4 Model Planning

题面说明：

- 计划购电量 > 调整购电量的差额：违约电价为交易时刻电价50%；
- 调整购电量 > 计划购电量的超出部分：按交易时刻电价1.5倍；
- 总费用包括计划购电、紧急购电和调整购电相关费用。

仍需明确：

- 下调时原计划对应的购电费用是否已全额计入后，再额外收50%违约费；
- 还是差额改按50%结算；
- “调整购电量”在模板中记录最终购电量还是变动量。

不同解释会直接改变目标函数。

**要求**：正式编码前先用符号和1—2个小数值例子手算验证结算规则，不能让 Codex 自行猜。

**要求**：优先证明/检查是否可在连续模型中自然排除，不应为了“看起来严谨”直接升级成 MILP。

# Issue Gate

进入不同阶段的最低要求：

### 进入 A-1 Preprocessing

可带着 OI-01、OI-03—OI-16 进入，但必须重点处理 OI-02 的原始结构问题。

### 进入 A-2 Recon

必须满足：

- OI-02 已完成全表审计；
- canonical 数据表和原始追溯关系稳定。

### 进入 A-3 EDA

必须至少保证：

- 10分钟 slot 的位置顺序稳定；
- 不需要利用未解决的 OI-01/OI-13 才能完成的分析不得强行执行。

### 进入 A-4 Model Planning

OI-01、OI-03、OI-04、OI-05、OI-06、OI-07、OI-08、OI-11、OI-12、OI-13 必须已经：

- 被解决；或
- 被转换为明确、可审查的模型假设/有限方案比较。

### 进入 A-5 Batch Run

不得仍存在会改变核心目标函数、状态方程或信息集的未决 Critical issue。
