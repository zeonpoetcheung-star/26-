## 1. 作图定位

P1 的 Codex 图均为 diagnostic figures，已经完成验证任务，不再继续美化。

B 的任务是基于 **A-route Final canonical 数据重新绘制 publication figures**。可以先查看 B 自己 Problem 1 现有的成图和绘图脚本，参考自己已经形成的布局习惯、字号体系、线型习惯和配色逻辑；但只能参考**视觉方法**，不能继续使用 B 的 H-START 数据。

最终图的数据源必须是 A Final：

```text
p1_schedule_internal.csv
p1_summary.json
p1_storage_4h_summary.csv
p1_specified_purchase_intervals.csv
KEY_RESULTS.csv
```

## 2. 最重要的时间约束

A Final 使用 H-END。

图中的物理时间必须按：

```text
0:10 source marker → 0:00-0:10
...
0:00+1 source marker → 23:50-24:00
```

绘图时应使用：

- `physical_interval`；
- `interval_start_hour`；
- 或由物理区间计算的中点。

**不要把 `source_marker` 直接当作区间左端点。**

这是硬约束。

## 3. 推荐最终只保留两张主图

### Figure P1-1｜全天能源调度与电价

目的：让读者一眼理解负荷、光伏、外网购电与电价的时序关系。

建议数据：

- `load_kwh`
- `pv_forecast_kwh`
- `purchase_kwh`
- `price_yuan_per_kwh`

建议采用统一的“每 10 分钟电量/kWh”作为主纵轴，从而避免在同一主轴混合 kW 和 kWh。

电价可以使用较弱的辅助轴或单独的小面板。不要让电价线压过主调度数据。

需要表达：

- 光伏高出力阶段外网购电下降；
- 高价时段购电受到抑制；
- 最优策略具有明显的时移特征。

### Figure P1-2｜储能充放电与 SOC

目的：同时说明储能何时充、何时放，以及 SOC 如何受边界约束。

建议：

- 充电量 `charge_bus_kwh` 画正方向；
- 放电量 `discharge_bus_kwh` 可画负方向，便于直观看出充/放切换；
- SOC 用单独纵轴画连续曲线；
- 1200、10800 kWh 边界可用非常克制的参考线表示；
- 0:00/24:00 的 6000 kWh 不需要用巨大标注强调。

这张图比把“充电、放电、SOC”拆成三张更紧凑，也更像正式论文图。

## 4. 不建议制作的图

除非论文版面有明确需要，否则 P1 不建议额外制作：

- 大号 KPI 卡片；
- 饼图；
- 雷达图；
- 只比较“优化前/后费用”的装饰性柱状图；
- 充满数值标签的 dashboard；
- 3D 图；
- 复杂 Sankey；
- 为了显得高级而增加的无信息图。

基准与 Final 的费用差异更适合放在表格和正文中。

## 5. “不要一眼 AI 味”的具体要求

这里不是故意做旧或做粗糙，而是保持真实论文制图的克制感。

请优先做到：

- 白底或与论文正文一致的简洁背景；
- 配色数量少、逻辑固定，不使用彩虹色；
- 不使用霓虹、渐变、发光、阴影、玻璃效果；
- 不使用大量圆角卡片或信息框；
- 不给每个数据点加文字；
- 不自动给每条线都加 marker；
- 图例、坐标轴、网格线保持轻量；
- 字号层级不要过度戏剧化；
- 标题简洁，图的解释交给 caption 和正文；
- 保留少量自然留白，不追求“每个角落都有信息”；
- 不做没有数据意义的平滑；
- 不重采样、不改真实调度值。

**优先延续 B 自己已有的绘图习惯。** 如果 B 原有的 P1 图已经有自然、统一的论文风格，可以直接复用其设计语言，只把数据替换为 A Final H-END canonical 数据，并重新检查时间轴。
