# Problem 2｜Candidate Limitations

1. **时间语义 OI-01**  
   内部采用 H-END；官方结果模板的文字区间与该解释存在结构性冲突。当前采用同日位置合同输出，不能宣称已获得官方唯一解释。

2. **当前槽快速响应假设**  
   actual controller 使用当前10分钟槽的代表功率进行储能响应。若数据只能在区间结束后获取，则该控制属于理想化的槽内快速平衡近似。

3. **Q80并非严格随机全局最优**  
   0.8分位来自无储能单时段的价格不对称近似；加入SOC耦合后，Candidate只是风险分位驱动的滚动优化。

4. **经验覆盖率**  
   Q80经验覆盖率约77.75%，不能称为严格80%保障。

5. **模型开发暴露**  
   Common阶段曾使用全年描述性统计，因此2—12月回放是严格限制运行时信息的历史回放，但不是完全 untouched holdout。

6. **控制器局限**  
   实际反馈主要关注当前缺口，并未证明最小化未来随机路径上的全年预期费用。

7. **终端设计**  
   48h内部使用 `S288=S0` 缓解有限时域末端效应，但它是作者设计，不是题目规定。

8. **完全信息参考**  
   约1222.67万元的完全信息放宽值只是条件下界参考，不能用作可实施策略答案。

9. **复现维护**  
   旧 `p2_dispatch.py` 的 oracle 缓存恢复分支缺少 `import json`；不影响冻结数值，但应在归档前修补并保留修改记录。

10. **跨平台浮点差异**  
    LightGBM 对极小特征差异可能跨越树阈值。Candidate必须冻结实际特征CSV、模型文件和运行环境，不依赖不同平台重新计算后逐位相同。
